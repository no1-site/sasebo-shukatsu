# 佐世保 終活相談窓口：無料集客・広告開始前の確認計画

更新日：2026-10-10

## 方針

**有料広告の出稿は、基本導線とコンバージョン計測を検証し、広告費の上限と成果指標に合意するまで保留する。**
無料でできるSEO改善・コンテンツの整備・地元での認知拡大を先行する。
この計画は準備・確認用の文書であり、広告を自動配信したり、お客様の個人情報にアクセスしたりしない。

## 現状（確認の根拠と未確認事項を分ける）

- [x] GitHub PagesでLP（トップページ）を公開済み。
- [x] Search Consoleでトップページと「墓じまい完全ガイド」の登録済み表示を利用者が確認。
- [x] 費用ガイドと改葬許可申請ガイドのインデックス登録リクエストを送信。
- [x] 3記事をまとめたブログ一覧 `blog.html` をGitHubに設置。
- [x] `analytics.js` にサイト固有のGA4測定ID `G-VN5SKDQH5H` が設定されている。
- [x] GA4で実問い合わせイベント `generate_lead` が発生することを過去に確認。
- [x] Google広告とGA4プロパティはリンク済み。
- [ ] Search Consoleのサイトマップエラーは未解決。個別URLの登録状況とは分けて監視。
- [ ] 新しいブログ一覧ページの公開状況・表示内容・スマホでの操作性を実機確認。
- [ ] LPと記事間の相互リンク（特にLP→ブログ一覧）の確認。LP本体は大容量のため不用意に編集しない。
- [ ] 検索パフォーマンスの実測値を取得（表示回数・クリック・クエリ・ページ）。公開直後のゼロだけでSEO効果を判断しない。
- [ ] Google広告のコンバージョンアクションにGA4の `generate_lead` が正しく取り込まれたか確認。**別事業「今日の売り出し」のタグは流用しない。**

## 第1段階：費用ゼロで最優先の整備

1. **導線確認**：スマホで記事→60秒無料チェック→問い合わせ送信の全過程をテストする。GA4イベントは実送信成功だけを成果として扱う。
2. **信頼性の確認**：運営者情報、問い合わせ方法、プライバシーポリシー、費用の対象範囲、行政機関でない旨、紹介・施工担当の責任範囲など、消費者が不安なく相談できる情報を精査する。
3. **SEOの土台**：記事ごとのタイトル、説明文、正規URL、相互リンク、モバイル閲覧、出典、FAQを点検する。現行 `site_health.py` と `seo_audit.py` の自動検査も利用する。
4. **計測の点検**：GA4の `page_view`、クイズ開始・完了、`generate_lead` を確認する。実送信成功件数とフォームの受信件数が概ね一致するか確認する。

## 第2段階：無料の集客実験（最初の2〜4週間）

- **検索意図に合わせた記事**：手続き、見積もり、遺骨の行き先、費用の考え方など。検索需要はSearch Consoleの実データで確かめる。単なるAI量産、既存記事の言い換え量産はしない。
- **既存記事の更新優先**：Search Consoleで表示され始めたページのタイトル・見出し・リンク・CTAを改善。新記事は出典と固有の価値がある場合だけ作る。
- **地元接点での紹介**：関係事業者・寺院等に、説明責任・紹介の同意・個人情報管理を守った形で情報提供を検討。無差別メール送信はしない。
- **SNSはブログの二次利用**：週2〜3本を目安に、費用・申請手続きの短い説明から記事へ誘導。SNS用の新規コンテンツを大量に作るより、既存記事の品質を優先。
- **Googleビジネスプロフィール**：実在する対面対応事業等としてGoogleの利用資格を満たす場合のみ検討。実体のない住所・架空店舗を登録しない。
- **メルマガは後回し**：希望していない方への配信をせず、配信希望者と配信目的が明確になった時点で導入を検討。

## 第3段階：有料広告の「配信前」ゲート

以下を確認するまで広告は公開しない。

- [ ] LPと問い合わせフォームをスマホで操作し、受付・通知・返信までの実テストが成功している。
- [ ] GA4 `generate_lead` は成功した問い合わせにのみ発生する。イベント重複・別事業タグ混入がない。
- [ ] Google広告のコンバージョンアクションに正しいGA4の `generate_lead` を設定し、最適化対象を確認した。
- [ ] 配信対象地域を、実際に対応可能な範囲に設定した（佐世保市・周辺の対応範囲を確認）。
- [ ] 検索広告のキーワード候補・除外キーワード・広告文・リンク先を確認。実際の検索需要や単価はキーワードプランナー等で検証。
- [ ] 説明可能な料金・広告表現・運営情報を確認。
- [ ] 一日の広告費上限、テスト期間、停止条件、成果の判定方法を**事前承認**。
- [ ] キャンペーンは初期状態「一時停止」で作り、配信開始は最終承認後に行う。

## 週1回、見る数字

1. Search Console：検索表示回数・クリック数・クエリ・ページ別変化。
2. GA4：自然検索の訪問、記事からLPへの遷移、60秒チェック開始・完了。
3. 問い合わせ：実件数、相談につながった件数。閲覧数より重要。
4. 問い合わせ率：実問い合わせ件数 ÷ LPへの訪問数（少数サンプルでは断定しない）。

## 注意事項

- `index.html` は大容量。GitHubの通常のファイル取得APIでは内容が空になることがある。既存の問い合わせ機能を保護し、完全な内容を取得・バックアップできる方法を確認するまで安易に編集しない。
- サイトマップ送信がエラーでも、トップページと既存ガイドのインデックス登録は確認済み。エラーの原因は断定せず、個別記事のインデックス登録・自然検索の実績を優先する。
- 広告費をかけること自体が目的ではない。検索意図、単価、問い合わせの質から投資可否を判断する。
- 確認済み・未確認を分けて記録し、見込みの数字や架空の実績をサイトに掲載しない。
