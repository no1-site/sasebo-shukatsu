- [ ] シートの既存列（特にQ列「成約有無」、R列「売上金額」）が変更・上書きされていない。
- [ ] 相談受付の連絡体制（誰がいつ確認し、どの連絡手段で折り返すか）が決まっている。

- [ ] 実機のスマートフォンでQ1〜Q7、結果表示、フォーム、同意、メール選択時の必須チェック、送信結果表示を確認する。

- [ ] 施工・供養などの紹介先、受け入れ可能地域、案件紹介の条件、報酬発生条件を合意する。
- [ ] 問い合わせ1件あたりの期待粗利益と許容獲得単価を算出し、予算を事前に承認する。

## 許容CPAの考え方
- 1件の「正式な見込み相談」に対する期待粗利益 = 案件成約時の当社粗利益 × 有効相談→成約率 - 相談対応などの変動費（必要に応じて紹介先の支払条件を反映）。
- 初期の許容CPAは、期待粗利益より十分低い水準に設定。実績ゼロの段階で成約率を事実として置かない。
- 「送信試行」は正式な有効相談ではない。重複・テスト・不達・営業を除外した件数で評価する。
- LPからのフォーム送信、受付成功、実際の相談、紹介、成約、入金を分けて管理する。

## 14日間の小規模検証で判断すること
1. 配信対象地域・検索語句が実際の需要と一致しているか。
2. クリック数に対して実際の問い合わせが発生したか。
3. 問い合わせの質・紹介先の対応・成約見込みを評価できたか。
4. 問い合わせあたり費用が許容CPA以下に収まる見込みがあるか。

継続・停止・広告文やLP改善は、取得データに基づきユーザー承認後に判断する。
